# 解説動画「動画の作り方 2026年11月」とプロセス動画（2026-11-09）

## 作り

- 型は talk（[[talk]]）。描き方は [[exp-html-capture-pipeline]] と同じ: canvas に時刻の関数 `renderFrame(f)` で描き、headless Chrome で 1 コマずつ撮って ffmpeg へ。
- 時刻表はナレーションの wav の実際の長さから作る（行間 0.45 秒、節の間 1.2 秒）。場面の切り替えも字幕もこの表に従う。
- 引用した西尾の動画（Gyazo の 47 秒版、THINKLET のデモ、tsugigami の宣伝動画）は、canvas に枠だけ描き、中身は ffmpeg の overlay で重ねた。
- 一本の手順を make.sh にした: galleria の合成音声を持ち帰る → 時刻表 → 描画 → 引用と音を重ねる → スマホ用。古い wav のまま書き出した事故（二回目）のあとに作った。
- 台本の言い切っている主張 15 個は、原典を開いて確かめた（[[explainer-script-factcheck-2026-11]]）。そのまま使えたのは 1 個。

## 声と読み

- 声は AivisSpeech「まお／おちつき」（[[exp-galleria-tts-and-singing]]）。読みの確かめは二つ:
  - faster-whisper large-v3 で文字に起こして台本と照合する
  - `/audio_query` の accent_phrases の拍を並べる（`kana` の欄は入力をそのまま返すので使えない）
- 誤読は H.264、2026、「ある時刻」など。どれも narration 側の表記を変えて直した（caption と narration を分ける）。

### 三つの声の聞き比べ

- 西尾「Aivis と VOICEVOX(ずんだもん) と Irodori とで比較したい」。全 33 行を三つの声で焼き、行ごとに再生して選べるページで比べた。
  - まお（AivisSpeech）
  - ずんだもん（VOICEVOX 0.25.2 CPU、ノーマル）
  - Irodori-TTS v4.1-Small（galleria の参照の束、seed 1）
- Irodori は galleria の venv が torch 2.10.0+cpu だったので CPU で回り、1 行 20〜80 秒かかった。半数以上の行でピークが 1.0 に触れた。全文の尺は、まお 6:26、ずんだもん 6:45、Irodori 7:05。
- 西尾「まおがいいな」。

### イントネーションの指定（AivisSpeech）

確かめたこと（2026-11-09）:
- アクセント句ごとの核の位置（`accent`）を書き換えて `/synthesis` に渡すと、F0 の山の位置が動く（「ひとつ」の核 1/2/3 で確かめた）。
- `moras[].pitch` は 0 で返る。一音ずつの高さは指定できない。
- 同じ入力でも波形は毎回少し違う。波形の差では効いたかを判定できず、F0 で見る。
- 句だけを切り出した query は 500 になる。候補は短い文脈の文（例「少なくとも三通りあって、」）を丸ごと合成し、対象の句を拍の文字列で探して書き換えた。句のつなぎ・切り直し（`reshape`）も通る。
- 句読点（「,」）が拍として句の末尾に入る。核をそこに置くと平板と同じ。

進め方:
1. 33 行を、アクセント句ごとに高低の線をつけた札として並べた（494 句）。西尾が気になる札に印をつけ、18 か所・9 語になった。
2. 語ごとに核の位置を全部変えた候補を、短い文で焼いた（57 本）。一語なのに途中で区切れていた語は、つなげた候補も出した。
3. 西尾が選んだ:
   - 平らに: 三通り・ひとつめは・止めたり・クロード・読み間違い
   - 区切らずに続けて「クロードオ↘ーパス」「ご↘ーてんご」（西尾「音を前後で区切るのが微妙」）
   - 文の書き換え（西尾「「に かなで」がそもそもへん」）
4. 選んだものは `tts/overrides.json`（行ごとに、対象の拍の文字列と切り方・核）に入れ、synth.py が合成の前に当てる。変えた行だけ合成し直した。

### 指定が効かなかった語（エフエフエムペグ）

- 一回目、核の位置を変えた候補は全部「どれも違う」（西尾「エムのムが高いかな」）。
- 二回目、「ム」を低くする 4 候補（「エムペグ」を核 1 と 2、前の「エフエフ」を核 1 と 4）。西尾「音声あってる？」。
- 拍ごとの F0 で比べた（プロセス動画のフォークが測った）。候補 1 と 2 はどちらも「エ↘ムペグ」（核 1）と指定したもの。
  - 候補 1 は「エ」に対してム +1.3・ペ +2.0・グ +1.0 半音で、指定と逆に上がった。
  - 候補 2 はム +0.4・ペ −0.2・グ −1.7 半音で、グだけ少し下がった。
  - どちらも指定どおりには下がらなかった。前の語の指定を変えるだけで、この語の形が変わった。
- 三回目に書き方を 5 通り試した（エフエフ、エムペグ／エフエフ・エム・ペグ／ffmpeg／エフエフエムペッグ）。西尾「諦めよう。breakはなしで」で、今の読みのまま。
- 教訓: 指定できる仕組みがあっても、反映されるかは語による。反映を確かめるには、表示と音を比べて測る。

### 確かめる側の誤り（F0 の測定）

- 最初の測定（Mac の Claude）は、自己相関の探索範囲の上限を 360〜400Hz にしていた。まおの声は 400〜480Hz で、上限が低いと半分の高さを拾う。その結果「4 候補の高さはほぼ同じ（220〜240Hz で平ら）」と西尾に報告し、西尾はその言葉で台本を直した。
- 測り直しで見つかった。スペクトログラムで倍音が約 450Hz と約 900Hz にあり、675Hz の帯が無いので、F0 は 450Hz 付近と分かる。YIN に倍・半分の手当てを足し、第 2 倍音の半分で検算した。
- Whisper の語の時刻は英字の語でずれた（「M」〜「グ」が実際には「エフエムペ」あたりだった）。拍の区切りはスペクトログラムと音量から読んだ。
- 教訓: 声の高さは、探索範囲をその声に合わせ、スペクトログラムの倍音で検算してから報告する。

## 学んだこと

- 合成音声のイントネーションは、AivisSpeech なら核の位置で直せる。ただし直す前に、指定が音に反映されるかを語ごとに確かめる。
- 計測を見せる場面は、主張そのもの（指定と結果のずれ）を図にする。説明文の画面写しやスペクトログラムだけでは伝わらない。
- 聞き比べは、どの音が鳴っているかの名札と、始まる前の一言が要る。
- 修正の話は、修正前を見せないと伝わらない。
