# 解説・発表の動画を MLLM に評価させる（EduPanel・Paper2Video）

## 何の文献か

- **EduPanel**（arXiv 2607.18529 v2、cs.HC、プレプリント）: 台湾大学の Hung-yi Lee のグループ。教育動画を、学習者の想定（学年・集中できる時間・前提知識の有無）つきでルーブリックに沿って採点する 3 エージェントの評価役と、専門家 12 人との比較
- **Paper2Video**（arXiv 2510.05096 v2、プレプリント）: NUS Show Lab（Code2Video と同じグループ、[[web-theoremexplainagent-code2video-visualedu]]）。論文から発表動画（スライド・字幕・音声・カーソル・話者の顔）を作る仕組みと、その評価指標。評価の一部に動画モデル（VideoLLM）を聴衆として使う
- どちらも PDF の本文を読んだ。EduPanel の repo の中身は読んでいない

## 書いてあること

### EduPanel（2026-07）

- **素材**: 4 分野（物理: 円運動とケプラーの第 3 法則、生物: 体細胞分裂と減数分裂、数学: 三角形の五心、CS: 過学習と未学習）× 各 3 本＝**12 本**。各動画に、作った狙い（big concept・Bloom の段・学習目標・要点）と想定の学習者が付いている（§3.1、Table 7）。著者自身が「意図して小さい、選んだ評価セット」と書く
- **ルーブリック**: 学習科学に基づく 24 指標から、予備試験で天井効果（どの動画にも満点近く）が出たものを除いた 10 指標。うち**画面の情報が要るのは 3 つ**（A1 事実の正確さ、C4 視覚的な説明の力、D2 視覚のデザイン）で、残り（話題の網羅、例・たとえ、埋め込まれた問い、考えさせる問いかけ、語彙の適切さ、前提知識への配慮、ペースの適合。ペースは文字起こし＋音声）は文字起こしで足りる、とルーブリックが定めている（Table 2）
- **評価役**: 3 エージェント（動画を見て時刻付きの内容の地図と事実・画面の誤りの候補を作る VLM、その報告を読んで客観的な観点 A1・A2 を採点するテキストの係、想定の学習者を演じて体験の観点を採点する VLM）（Fig. 1）。全員 `gemini-3-flash`（preview の固定版、temperature 0、seed 42）。1 本を 3 回採点して平均（§3.2）
- **人**: 専門家 12 人が 12 本を 2 回採点（1 回目は単独、2 回目は AI の講評つき）。一部の AI の点は意図的に 2 点以上ずらした「仕込みの誤り」（26 個）
- **結果**（§4.1、Table 3・4）:
  - AI を見ない人の合議に対して、EduPanel の MAE 0.85。**単独の専門家の中央値は 0.87**（範囲 0.58〜1.00）。人どうしの一致は α 0.38（中程度）
  - 誤差は**文字起こしで足りる観点で小さく、画面に依る観点で大きい**。Gemini では画面に依る観点で +0.67、文字起こしの観点で +0.24 **甘い**
  - **文字起こしだけ**にすると MAE 0.55 → 1.07、1 点以内 92% → 72%、相関 r 0.84 → 0.23。点が中央に寄る（SD 1.44 → 0.66）。「動画は欠かせない」
  - 3 エージェントを 1 回の呼び出しにまとめても MAE は同じ 0.55（相関は 0.84 → 0.78）。学習者の想定を外すと学習者への適合の観点だけ悪化（0.42 → 0.90）
  - 同じ仕組みを GPT（**コマを抜き出して入力**）で回すと、合議に対する MAE は 0.87 で Gemini（0.85）と同程度。画面の観点で甘くなる偏りは GPT では出ない（+0.06）
  - 再実行の揺れ: 同じ構成でもう一度回すと MAE 0.60（±0.05 は揺れの範囲とみなす）
- **人の作業への効き方**（§4.4）: AI の講評を見ると専門家の誤差が 0.87 → 0.73。**仕込みの誤りを見分けられた**（AUC 0.77）。AI が専門家全員の見落とした誤りを指摘した例: 減数分裂の動画でナレーションが「DNA の複製は第一分裂前期」と言っていた（正しくは間期の S 期）。12 人全員が単独では見逃し、1 人は「判断する専門知識が無い」と書いた。同様の補完の例は多くて 16 件（上限の見積もり）
- 著者の結論: 「専門家の**置き換えではなく、補助**として使える」

### Paper2Video（2025-10）

- 101 本の論文と著者自身の発表動画（2〜10 分）を対にしたデータ。評価指標 4 つ: Meta Similarity（人の作ったスライド・字幕・声との類似）、**PresentArena**（動画モデルが 2 本を見比べてどちらがよいか、順を入れ替えて 2 回）、**PresentQuiz**（動画モデルが動画を見て論文の問いに答える正答率）、IP Memory（覚えているか）。動画モデルは Gemini 2.5 Flash（§5.1）
- 結果（Table 2）: PresentQuiz は、作った動画（PaperTalker、平均 234 秒）が細部 0.842・理解 0.951 で、**人の作った動画（平均 375 秒）の 0.738・0.908 より高い**。著者は「人の作った発表を正答率で 10% 上回る」と書く。一方 PresentArena では、人の作った動画に対する勝率は 17.0%
- **人の評価**（10 人、10 本の論文、1〜5 の順位付け、Fig. 6）: 人の作った動画 4.6、PaperTalker 3.8、ほか 1〜2.8。人は人の作った動画を上に置いた
- 動画モデルは「話者の顔が出る発表を好む」（話者とカーソルを外すと Arena が 1.8% 下がる）、カーソルがあると小テストの正答率が上がる（動画モデルが要点の場所を見つけやすくなる、と著者の解釈）

## この wiki への含意

- **talk の批評役は「文字起こしだけ」では足りない、を測った数字がある**: EduPanel で文字起こしだけにすると相関が 0.84 → 0.23。西尾の talk（[[exp-qualia-video]]、[[exp-llm-wiki-explainer-series]]）の「その瞬間の画面が説明を助けているか」（qualia の v2 → v3 の見直し）は画面を見ないと判定できない。逆に、文字起こしで足りる観点（話の順序・用語の難しさ・学習者の前提）は、台本の段階でテキストの LLM に見せればよい
- **ただし画面に依る観点ほど甘い**: Gemini は画面を見ると点を上げすぎる。qualia の「意味のない飾り画像の面積が多すぎる」（v3 への人の指摘）や Gyazo の「268群って何？」（[[exp-gyazo-resumption-video]]）のような、画面が悪いという指摘こそ、甘い評価役が見逃しやすい側にある、と読める（このページの推論）
- **一番効きそうな使い方は「事実の誤りの指摘」**: 専門家 12 人全員が見逃したナレーションの誤りを拾った例がある。西尾の talk は題材の正しさを第三者が確かめた記録が無い（after-opus55 の Open Questions）。批評役に「ナレーションと画面の主張で事実として誤っている所」を時刻付きで挙げさせるのは、人の確認の前段として筋がよい。採否は人が決める（AUC 0.77 は人が誤りを見抜けることを示すが、全部ではない）
- **動画モデルを「聴衆」にした小テストは、人の好みと逆を示すことがある**: Paper2Video で、短く要点の詰まった生成動画のほうが小テストの正答率は高く、人は人の作った動画を好んだ。Code2Video の TeachQuiz（[[web-theoremexplainagent-code2video-visualedu]]）も学習者は VLM だった。「批評役が要旨を言えた・問いに答えられた」は、人が見て分かる・見たいと思うことの代わりにならない。howseen の「新しいエージェントにコマだけから要旨を言い直させる」（[[web-opus-howseen-claude-motion-design]]）も同じ限界を持つ
- **想定の見る人を渡す**: EduPanel は学習者の想定を外すと、学習者への適合の観点が倍悪くなった。西尾の型では、talk なら「誰が見るか」（未踏ジュニアの応募者、社内、X のタイムライン）、embed なら「発表の聴衆が、話し手が黙っている間に見る」を批評役に渡すことになる。[[origin-2026-11-09]] の「型を決めたのは流す場所」と同じ軸

## 着手の仕方（未検証。galleria で確かめる）

- **何ができるようになるか**: talk の動画を、①台本（テキスト）の段階でテキストの LLM に、②完成動画の段階で動画を見られるモデルに、と 2 段で批評させる。②では「想定の見る人」と「狙い（一文の要旨・要点 3 つ）」を一緒に渡し、事実の誤り・画面が説明を助けていない所を時刻付きで挙げさせる。型: talk。embed は「話し手が黙っている間に、聴衆が何を読み取るか」に置き換えて試す
- **機械**: どこでも。②は Gemini（**要: API キー・費用（西尾が決める）**、[[web-means-critic-gemini-video-understanding]]）。EduPanel の公開 repo を使う場合は galleria WSL（中身は未読なので、依存・ライセンスは repo で確かめる）
- **成熟度**: EduPanel は 2026-07 のプレプリント。12 本での結果
- **最小の手順**（渡すものの形は EduPanel の §3.1 の course requirement と student persona を西尾の制作向けに縮めたこのページの案）:
  1. 作品ごとに `brief.md` を作る: 狙いの一文、要点 3 つ、想定の見る人（誰か・前提知識の有る／無い・何分見るか）、流す場所
  2. Gemini に動画（音あり）と `brief.md` を渡し、(a) 事実として誤っている主張、(b) 画面が説明を助けていない区間、(c) 想定の見る人が置いていかれる語、をそれぞれ別の問いで、時刻付きで挙げさせる（問いを分けるのは [[web-means-critic-video-bench-spotlight]] の結果から）
  3. 同じ動画を文字起こしだけで (a)(c) を聞き、動画ありとの差を見る
  ```bash
  # 文字起こし（3 の比較用）。Whisper 系をローカルで使うなら galleria の既存の環境で（担当外のため手順は省略）
  ffmpeg -i in.mp4 -vn -ac 1 -ar 16000 voice.wav
  ```
- **動いたと言える確かめ方**: (a)(b)(c) がそれぞれ時刻付きで返る。過去の作品で人が指摘した箇所（qualia journey の初版への「細かい数値を耳で聞くのが辛い」「図解が多すぎる」、[[exp-qualia-video]]）が、(b)(c) に含まれるかを数える。動画ありと文字起こしだけで、指摘の数と中身がどう違うかを記録する
- **所要（推測）**: `brief.md` の作成 30 分、1 作品の比較で 1〜2 時間

## Open Questions

- EduPanel の人の正解は、2 回目に AI の講評を見た合議を含む。AI を見ない合議に対する数字（MAE 0.85）を主に見るべきと著者自身が書く
- EduPanel の 12 本は 4 つの話題 × 3 本で、尺・作り方（人が作ったか生成か）の詳細は本文の表に無い（付録の表も話題だけ）
- Paper2Video の人の評価は 10 人・10 本で、順位付けの平均。小テストの正答率と人の好みのどちらが「伝わった」の指標として正しいかは決着していない
- 日本語の教育動画で同じ測り方をした研究は見つけていない
