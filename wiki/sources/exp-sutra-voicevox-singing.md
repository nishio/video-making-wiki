# VOICEVOX の歌唱 API で読経・歌を作る

## 何を作ったか

sutra-videos の全作品の声は VOICEVOX（ずんだもん、波音リツ、四国めたん・春日部つむぎ・冥鳴ひまり、青山龍星・玄野武宏など）で合成した。読経も真言も「単音の歌」として扱い、替え歌・カノン・第九では旋律つきの歌にした。最初の道具は火界咒の `scripts/kakaiju_synth.py`（2026-07-24〜25、commit `7eb027d`）で、以後のスクリプトはこれを呼ぶ。

## 話し声 API ではなく歌唱 API

火界咒の音声化で試した結論（火界咒音声合成ツール「技術的な要点」）:

1. **話し声 API（`audio_query`/`synthesis`）は読経に使えなかった**。長い母音を指定すると後半が息混じりに減衰する（「風の音みたいな h 音」）。波形ループや PSOLA での補修でも人工的なビープ感が消えなかった
2. **歌唱 API が正解だった**。クエリは歌唱モデル（波音リツ sing=6000）で `sing_frame_audio_query`、声は `frame_synthesis`（ずんだもん 3003 など frame_decode 型のスタイル）。ロングトーンを学習しているので伸ばしが自然
3. リズムは楽譜で厳密に与える。かなからモーラへの分割をテキスト解釈に任せると揺れる（「びゃーく」がビ・ヤに割れた）ので、譜面側でモーラを確定させる
4. 歌詞に「ー」を渡すと 400 で拒否される。伸ばしながら音程を変えるには同じ母音のカナを続ける（マ→ア。音素列 m,a,a でレガートにつながる）か、合成前の f0 を書き換える
5. 10フレーム（約0.1秒）未満の休符があると `sing_frame_audio_query` が 500 で落ちる。前の音に吸収して回避した（残テの割り付け「技術メモ」）

## テンポはエンジンのフレームに合わせる

VOICEVOX は 93.75fps で時間を刻む。指定した長さは丸められる。

- 190ms/拍の指定は 18フレーム＝192ms になった。映像側も 192ms で計算しないとずれる（漢文偈・般若心経）
- アゲアゲ版は逆にこれを利用した。1モーラ＝16分音符とし、11/9/8フレームで 128/156/176BPM に**端数なく**乗るテンポを選んだ（般若心経漢字版の制作 2026-09-25）
- 第九は 84BPM 指定で、1拍67フレーム＝実効 83.955BPM

## 人が直せるリズムの書き方

時間の正本はテキストにして人に直してもらう。形式は試行で固まった（[[exp-sutra-sync-subtitles]]も参照）。

- 真言・経: 空白＝区切り、`ー`＝1拍延長、`・`＝1拍休止。改行・空行は編集上の区切りで、**自動で休止にしない**
- 替え歌: 原曲の歌詞1行＝`wari.txt` の1行。`字[読み]`（`.` で音を分ける、`ー`＝前の音を延ばす、カタカナ＝母音を落とす、`+`＝伸ばし音を縮めない）、`(分け合う字)`、`{省く字}`、行内の `/`、行末の `〜`。全行をつなぐと般若心経と一字も違わないことを毎回検査する（残テの割り付け）
- 火界咒の譜面: `かな | モーラ:音高 ...`、`>` で伸ばし中の音程変化、`@beat_ms`、`@transpose`。モーラ数や音名の誤りは行番号つきエラー

**機械の中立初稿は作り込まない**。真言言えるかなの初稿は「4モーラずつ均等に詰める」だったが、本人が `rhythm.txt` を直接編集してほぼ全面的に書き換えた。差には型があった:「おん」＋3モーラの5モーラで入る（おんあびら）、結びの「か」を伸ばす（そわかー）、繰り返しの間は末尾の休止で決め、その長さは尊ごとに違う＝耳で決めている。人が直す前提の初稿は「それらしく」作らず、編集しやすさ（1行＝1回分、時間を変える記号は少数）を優先したのが効いた（真言言えるかなの設計と校訂 2026-09-26）。

伝承のリズムが分からないうちは全かな1拍の中立初稿から始め、人が空白・`ー`・`・` を足す（sutra-videos/CLAUDE.md）。漢文偈では各行の拍数を表示し、揃っていなくても機械的に揃えず試聴で判断した（五大尊名号の東方・中央句は本人の耳で 24拍に伸びた）。

## 歌詞の載せ方で出た音の罠

残テ・第九・カノンで、本人の耳で見つかったもの。

- **1音1モーラが基本**。読経の1字1音で組んだら「かん」「しょう」が1音に押し込まれて早口になった
- **伸ばし音は言い直さない**。「くう」を「く・う」にすると「くそく」（空即）と聞こえた。余った音に母音を置くと「そうお」になる。前の音を延ばして音程だけ移す
- **2モーラを1音で歌うとき**は普通は1モーラ目を長く（やーーーく）。ただし無声化しやすい組（しき・くつ）は逆に1モーラ目を短くする。第九の初稿は「しき」を1拍ずつ等分して、西尾「『しき』のリズムの取り方がおかしいな」。し0.25拍＋き1.75拍の v2 を作った（採否待ち）。残テで既に分かっていたことを初稿に反映できていなかった（既存曲に般若心経を載せる制作ノウハウ 2026-10-11）
- **短い音の次の子音は潰れる**。VOICEVOX は子音を音符の頭より前に置き、前の音の終わりから時間を取る。是大神呪で「じん」が約0.12秒の音に詰まり、次の「しゅ」の sh が約21ms しかなかった。`神[じ.ん]` にして sh は約107ms に（commit `d5bd065`）。「子音で始まる字の直前に、短い音を置かない」
- **高い音・長い音には開いた1音節**。残テ B2 の違和感は本人も「どうおかしいか説明できない」だったが、図にすると最高音で「やく」の k が音程を乱していた。原曲はそこに「な」1音だけ
- **1モーラの音は狙った音高に届きにくい**。アゲアゲ版で、1モーラの音は約67%が1半音以内、2モーラ以上は約96%。高い音は2モーラの音に置くと届く
- **ん・っ・子音で終わる字は前の音の高さのまま伸びる**。次の拍頭へはみ出すと和音外になる（カノンの和声検査で3回はまった）
- **短い音は指定した音名どおりに鳴らない**。火界咒の低音域で D♯3 指定の短音が実測約181Hz になり、E3 指定（約166Hz）より高く聞こえた（本人「D#がEより高く聞こえる」）。D3 では下がり、C♯3 ではまた跳ねた。通常音域（G♯3/A3/A♯3）では順序を保った。音高が大事なら公開条件そのもので WAV を実測する（録音から火界咒譜面を作る 2026-08-11）
- 話者の声の作り方そのものに由来する違和感は、波形を局所的に直しても消えなかった。残テの真実不虚の「こ」が「きょ」に聞こえる件は、スペクトルに違いが見えず、境目・音程・帯域・移植を試して、消えたのは声を春日部つむぎに替えたときだけ。1音だけ声を替えるのは本人が「変」とし、「ここの修正は諦めて」で据え置き

## 毎回結果が変わる段がある

`sing_frame_audio_query`（音程の揺れなどを決める段）は同じ入力でも毎回違う結果を返す。`frame_synthesis` は同じ入力なら同じ波形を返す（2回合成して確認、残テの割り付け 2026-10-01）。

- そのため作り直すと**直していない行まで少しずつ変わる**。本人が「他を作り直さなくていい」だったので、作り直した音声から1行の区間だけを行間の隙間で前の音声に切り貼りした（15ms で重ねる。区間の外は前の音声との差がエンコード誤差 −29dB 以下）。全体を作り直した版と聴き比べた本人の評価は「どっちも大差ない」
- 採用した音声とクエリを残しておく。第九ではクエリ・音声をキャッシュし、合成後の音量調整はキャッシュした歌声を再利用した
- 伴奏が毎回同じ波形なら、ミックスから伴奏を引けば歌声だけ取り出せる（AAC の頭の遅れ119標本と音量1.185倍を合わせると残差 −35dB）

## エンジンの運用で起きた事故

- **メモリを解放せず溜める**。約1時間・数回のカノン試作書き出しで 62GB、スワップ枯渇寸前。1声（約200秒）の1回の合成で 15〜16GB まで膨らむ。自分で起動したエンジンは書き出しのまとまりごとに止め、次の合成の前に起動し直す。カノンの全編は `canon_synth_voice.py <声番号>` で1声ずつ「起動→合成→停止」してキャッシュに入れ、最後に組み立てる。プレビューは区間の1周手前からだけ合成（10分超→31秒）（sutra-videos/CLAUDE.md、般若心経のカノンの制作 2026-10-07）
- **並行 session とポートを取り合う**。全編合成中に別 session が同じ port 50121 のエンジンで試聴を作っていて、3声目の合成が失敗した。合成の前に `pgrep -fl "port 50121|make_sutra_canon"` と `build/audio` の最新ファイルの時刻を見る。別の作業が止め忘れたエンジンが 28GB 抱えていたこともある
- 第九のスクリプトは、既存の VOICEVOX プロセスへ接続も停止もせず、専用の port でエンジンを起動して finally で止める形にした（`make_ode_to_joy_short.py`）
- 既定の 50021 は Ollama と衝突したので 50121 で起動した（火界咒音声合成ツール）
- galleria（Windows）ではエンジンが Windows 側にあり、WSL から届くかを最初に確かめる必要があった（zankoku-hannya/HANDOFF.md）

## ミックス

- **声が伴奏に埋もれる**。アゲアゲ版の初回は声を足しても 800–4kHz 帯が +1dB しか増えなかった。声をピーク正規化して別バスで最後に重ね、声の帯域で伴奏比 +8〜11dB にした。耳で聴けない環境では**声あり／なしの帯域 RMS 差**で確かめられる（般若心経漢字版の制作 2026-09-25）
- カノンの強調（その声だけ音量を上げる）は 5→10（大きすぎ）→7→5dB と振れた末、v2 で**音量の操作を全面廃止**し、目立たせ方を「声がそろうこと」に置き換えた（本人の判断）

## 録音から音程を写す実験は公開工程から外した

本人の火界咒の録音から、MFCC-DTW で小節長を、pYIN 系で F0 を推定して譜面にする実験をした（録音から火界咒譜面を作る 2026-08-11）。

- 可変リズム版: 本人「イマイチ、そんなに変わってない、誤判定」
- 可変音階版: 概ね近づいたが局所的な違和感が残り、短音では上の音高逆転が起きた
- 本人の最終評価「録音からの音程調整はイマイチうまくいかないため、やめる」（2026-08-12）。公開用は**一定テンポ・固定音程**を標準にし、録音は読み・句切り・全体の速さを人が確かめる参考に限った
- 一方、音程を1拍1文字の輪郭（`_-^x`）で表すビューは、自動推定版と手編集版の差を人が見つけるのに役立った。ただしこれは正本ではなくレビュー用
- 読経の音声認識は当てにならなかった: whisper-1 は反復崩壊、gpt-4o-transcribe は無音区間に長文の経典を幻覚した。ASR に本文も区間の実在も決めさせない（同 2026-09-14）
- 録音が役に立ったのはテンポ・打点・鐘の倍音を**測る**ときだった。実地の読経は約210BPM（1字285ms）、太鼓の打点の69%が285ms の整数倍、鏧の倍音 812/1219/2238/3640Hz。これがそのまま漢字版の既定テンポと鐘の合成に使われた（般若心経漢字版の制作）

## 西尾のフィードバックの受け方

- 音だけでは「わからん」。歌っている字が光り、字をクリックするとそこから再生し、字の下に音の高さを出すページを作った（`canon_solo_page.py`）。行番号と拍で指してもらうと直しが速い
- 言葉にできない違和感は、原曲の歌詞を同じ声・同じ旋律で歌わせた参照と、拍・楽譜の音・実際の f0・音素区間・再生位置を重ねた図で見える化した（[[exp-sutra-songs-on-music]]）

## 再利用できる部品

- `scripts/kakaiju_synth.py` — 歌唱 API の呼び出しと譜面記法（docstring に使い方）
- `scripts/canon_synth_voice.py` — 1声ずつ合成してキャッシュ
- `scripts/make_ode_to_joy_short.py` — 専用 port でのエンジン起動・停止、`--prepare`→`--synthesize`→`--render` の段階分け
- `zankoku-hannya/render.py`, `fit.py` — 替え歌の割り付けと合成（ただし原曲の track・区間音数・サビ位置を固定していて、別曲には分離が要る）
