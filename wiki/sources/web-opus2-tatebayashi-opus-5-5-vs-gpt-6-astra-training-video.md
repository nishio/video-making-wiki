# 「Opus 5.5 vs GPT-6 Astra を実務で比較」— 研修動画とショート動画（note、2026-09-25）

## 何の文献か

- 生成 AI の解説書の著者で YouTube・Udemy の講師が、自分の YouTube 動画の内容を記事にしたもの（note）。実務家の試用記で、評価は著者 1 人の主観。同じ指示・同じ素材で各モデル 1 回ずつ作らせた比較で、反復や採点の基準は書かれていない
- 著者は Higgsfield（画像・動画・音声の生成サービス）の MCP を使う手順と費用を詳しく書いており、紹介の性格もある（記事内に宣伝の表示は見当たらない）
- 作業は Claude のデスクトップアプリ（チャット）で行った、と書く（Claude Code ではない）

## 書いてあること

### 課題と指示

- 素材: 経理を想定した架空の Word 資料 3 つ（よくある質問の一覧、経費精算・備品購入の社内規定、職務権限・承認規定の一覧）
- 指示文（原文）: 「添付した3つの資料をすべて読み込み、新入社員向けに経費精算、備品購入、社内承認の基本を説明する2、3分の研修動画を作成してください。資料をそのまま要約するのではなく、重要な情報を取捨選択し、初心者が理解しやすい順番に再構成してください。Higgsfield、キャラアニメ、プロジェクトの既存環境を使い、Higgsfield MCPで必要な素材や音声を生成し、Remotionでモーショングラフィックスを使ったプレゼンアニメに仕上げてください。完成後にセルフチェックをして、必要なら修正してください。」
- 「Higgsfield、キャラアニメ、プロジェクトの既存環境」は、著者が別の動画で紹介した「キャラクターアニメーションの全自動プレゼンを作るための環境」と書く。つまり白紙からではなく、用意したプロジェクトの上で動かしている

### 結果（著者の評価）

- Opus 5.5 の研修動画: 「演出についてはほとんど何も指示していません。全体の組み立て、モーショングラフィックの綺麗な動き、説明に合わせて資料がだんだん出てくる見せ方まで、Opus 5.5が自分で考えて作ってくれています」「フルボイスで字幕付き」「約2〜3分」
- GPT-6 Astra の研修動画: 冒頭で 3 ステップを示したのに、ステップに無い話（備品や共用在庫の確認）が始まり、「3万円未満でも所属長の承認後」という表示が、3 万円のルールを説明する前に出た。「情報を渡す順序が逆になった構成」。見た目の完成度は Opus 5.5 と同じように感じた、と書く
- 著者のまとめ: 差が出たのは「何を・どの順番で・どのくらいの情報量で伝えるかという『説明の設計』」

### 作業の流れとセルフチェック（作業ログを見た著者の記述）

- 資料の把握 → 見せ方を含めた全体の構成 → 台本 → Higgsfield MCP で音声合成 → Remotion でモーショングラフィックス。必要な画像も Claude が計画し、Higgsfield の画像生成で作った
- 「日本語の音声読み上げは意外と難しく、漢字の読みを間違えて読み上げてしまうことがあります。そこでClaudeは、一度音声を作ってから、それをもう一度文字起こしして、正しく読み上げられているかを確認していました。間違っている場合は読みを直し、音声合成をやり直すという修正まで自ら行ってくれています」
- 費用: Higgsfield の消費は音声合成とイラスト 7 点で 5.5 クレジット。最安の月額プラン（月 19 ドルで 270 クレジット）に換算して約 58 円、と著者が Claude に計算させた。Claude 側の利用料は含まない。動画生成は使っていない

### ショート動画（20 分の自分の YouTube 動画 → 30 秒・1 分）

- Opus 5.5 は、背景だけ Higgsfield で動画生成し、その上にモーショングラフィックスの図解を重ね、元動画から必要な部分をテロップ付きで切り出し、最後に本編へ誘導する構成にした
- 著者の気づき: 「単に切り抜くだけだと分かりづらくなってしまいます」。意味が分かる順に組み立て直させ、ナレーションを新しく作る・モーショングラフィックスで説明を足す・動画生成でイメージを伝える、を組み合わせて「新たな動画として再設計させる必要」がある
- GPT-6 Astra のショートは「言葉数が少なく説明が足りない」「ロボットのような印象」

## この wiki への含意

- **talk の日本語の実例**: 2〜3 分・ナレーションと字幕付き・Remotion で描いた研修動画。[[exp-qualia-video]]（8 月、galleria の Codex が Pillow の静止スライド＋TTS で作った 93 秒〜6 分 33 秒）と同じ型を、9 月以後は別の道具の組み合わせ（Remotion＋外部 TTS の MCP）で作っている
- **読みの確認を文字起こしで機械にやらせる**: [[exp-galleria-tts-and-singing]]・[[exp-qualia-video]] は「表示文と読み上げ文を分ける」「それでも通し視聴で聞き違える読みが残った。最後は耳」だった。著者の報告ではモデルが「合成 → 文字起こし → 照合 → 読みを直して再合成」を自分で回した。文字起こし（ASR）は同音の別語を区別できないことがあるので、この確認で見つかる読み違いは一部と考えられる（推測。著者は精度を書いていない）。西尾の側で Whisper を歌の評価に使ったときは「良し悪しの判定にならなかった」（[[exp-galleria-tts-and-singing]]）が、これは音程の評価で、話し言葉の読みの確認とは別
- **「説明の設計」が差になった**: 著者の比較では、見た目は同等でも順序の崩れ（ルールを説明する前に使う）が伝わりにくさを生んだ。talk の台本の骨格（[[talk]]）の「動機 → 仕組み → 結び」と、誤概念・前提の順を守ることが、モデルの選択でも効く、という観察。ただし 1 回ずつの比較
- **切り抜きは説明にならない**: 長い講演から短尺を作るとき、切り抜きだけでなく組み立て直して足りない情報を補う必要がある、は [[exp-democracy-river-video]]（34 分の講演を 60 秒にするとき、字幕と年表で組み直した）と同じ結論
- **用意した環境の上で動いている**: 「既存環境」（キャラアニメ用のプロジェクト）と MCP を前提にした結果で、白紙のモデルの能力ではない
