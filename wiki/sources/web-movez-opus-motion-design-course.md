# Movez「How to build motion design studio with Opus 5.5」（2026-09-27）

- 著者: Movez（@0xMovez）、X の長文、2026-09-27
- **読み方の注意**: この wiki では元の投稿を開いていない。西尾が 2026-09-30 に tweet-memo に貼った本文の、tweet-memo 側の要約（`sources/movez-opus-motion-design-course.md`）から書いた。再生数・「12時間」などの個別の数字は、tweet-memo でも元投稿で確かめていない

## 書いていること

- Opus 5.5 は動画を直接出力できない。流行した動画はどれも、**時刻 t のフレームを描く純関数 `seek(t)` をモデルが書き、headless ブラウザで 1 枚ずつ撮って ffmpeg でつないだもの**、と書いている
- 「ワンショット」と書かれた作品の裏には 9,500〜19,000 字の指示書・スキル・API キー・12 時間の自律実行があることが多い、と Claude Code チームの Thariq の言葉を引いている。標語は「プロンプトは動画の10%、残り90%はハーネス」
- 差分を 4 つに分けている（tweet-memo の整理）:

| 欠けているもの | 記事の処方 |
|---|---|
| 参照 | 好きな動画を 0.5 秒ごとに切り出して style_guide.md を書かせる。「参照の文法を取り、内容は取らない」 |
| 描画エンジン | `seek(t)`＋閉形式のスプリング＋種付きの乱数（決定的に描き直せる） |
| 音 | 合成するなら絵と同じ時間軸で。既存曲なら librosa で拍を測って `beats.json` |
| 自分のフレームを見ること | 1 拍 1 枚のコンタクトシートと 360px 幅のスマホ試験を見て、フック・可読性・動き・変化・音の同期を 10 点満点で採点。ワースト 3 を直し、全項目 8 点以上まで回す |

- 既定で出てくる見た目（グラデーション背景に中央の文字、全部フェードイン、四隅のラベル、汎用のパーティクル）は「禁止リスト」として house rules に書け、としている
- 一行プロンプト（「履歴書用のショーリール」）は、**エンジンの試験にはなるが、アイデアの試験にはならない。アイデアを含んでいないから**。同じ一行から似た動画が大量に出る現象を、athemeroy のデータセットが "brief contagion" と呼んでいる、と紹介している

## この wiki の経験との突合

- **描画の方式は西尾の方式と独立に一致していた**: canvas＋`renderFrame(f)`＋puppeteer＋ffmpeg、BGM は numpy の合成（[[exp-html-capture-pipeline]]。2026-09-25 の [[exp-nishio-showreel]] から）
- **showreel の 15 秒版の依頼文は、この記事の言う一行プロンプトの形だった**（[[exp-nishio-showreel]]、[[exp-timeline-2026]]）
- **Polis のエヴァ OP 様式の動画は、記事を読む前に記事の段階をなぞった**（tweet-memo の突合節）: v1 は「しょぼい」（記事の言う "mid" な一回目）。v2 で効いたのは参照の文法で、映像ではなく Wikipedia の構成記述（90 秒・84 カット、平均 1.07 秒）を使い、v1 のカットが 4.5 秒と 4 倍以上遅いのが主因と分かった。v3 に記事の批評ループを当てると、アウトロ 10 秒の静止クレジットが「死んだ拍」だとコンタクトシートで初めて見えた（[[exp-polis-magi-op]]）
- 「文章で書かれたショット構造でも参照として働く」は記事に無い観察（tweet-memo）

## 記事に無いこと・食い違うこと（tweet-memo の整理）

- 汎用の採点軸（「最初の 2 秒でフック」）と参照の文法がぶつかる。エヴァ OP は静かな青い点で始まる。様式を借りるときは、どの採点軸を参照の文法が上書きしてよいかを決める必要がある
- 参照の入手そのものが制約になる（商用アニメの OP を保存する経路は限られる）
- 既存曲を使う場合の権利（作曲の権利と原盤の権利は別）を扱っていない
