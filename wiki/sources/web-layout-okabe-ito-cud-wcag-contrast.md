# 色覚の多様性への配慮と明るさのコントラスト（Okabe & Ito の CUD、WCAG 2.2）

## 何の文献か

- **岡部正隆・伊藤啓 "Color Universal Design (CUD) – How to make figures and presentations that are friendly to Colorblind people"**: 二人とも強い第一色覚（protanope）の研究者が、学会発表・論文の図・スライド向けに書いた手引きの Web ページ（Jfly、2002-11-20 公開、2008 年に 2 回改訂）。**本文を読んだ**。推奨配色（Fig.16）は**画像で示されていて、RGB の数値は本文に書かれていない**
- **W3C "Understanding WCAG 2.2"** の 1.4.1 Use of Color、1.4.3 Contrast (Minimum)、1.4.6 Contrast (Enhanced)、1.4.11 Non-text Contrast: Web のアクセシビリティ基準の解説（規範ではなく意図と根拠の説明）。**本文を読んだ**。2026-11-09 時点の公式ページ。Web ページ向けの基準で、動画の画面そのものへの適用は書いていない
- 第 1 回の [[web-powerpoint-keynote-google-slides-video-playback]] に色の話は無い。点滅（WCAG 2.3）と字幕の文字の大きさは扱わない（別の担当の領域）

## 書いてあること

### CUD（岡部・伊藤）

- **頻度**: 「赤緑」色覚の男性は白人で 12 人に 1 人（8%）、アジア人で 20 人に 1 人（5%）、アフリカ系で 25 人に 1 人（4%）。「250 人の部屋には 10 人以上いるはず」と書く（男女半々を仮定）。査読者 3 人が白人男性なら、少なくとも 1 人が色覚の多様性を持つ確率は 22%（1−0.92³）と計算して見せる
- **3(+1) の原則**:
  1. 実際の照明と使う環境を考えて、どの色覚の人にも見分けやすい配色を選ぶ
  2. **色の違いだけでなく、形・位置・線種・塗りのパターンを組み合わせ**、色を区別できない人にも情報が伝わるようにする
  3. 色名で会話することが想定される所では、色名を明記する
  4. （+1）そのうえで、見た目に優しく美しいデザインを目指す
- **redundant coding（冗長な符号化）の例**（Fig.14・15）: 線を太く・記号を大きく（色を感じる錐体を多く使える）、実線と点線で区別、点の記号を変える、**凡例を離して置かず、ラベルを図の中に直接細い線で結んで書く**（離れた二か所の色を照合するのは、数 cm 離れているだけでも難しい）、塗りにハッチングを足す。これで白黒コピーやファクスでも情報が落ちない、と書く
- **色の選び方**（冗長な符号化を済ませた**後に**適用する、と明記）:
  1. 重要な情報を色だけで伝えない
  2. 文字と背景の**明るさと彩度の差**を十分に取る。明るさが同じで色相だけ違う組み合わせ（緑地に赤字など）は避ける。明るい字に暗い地、またはその逆
  3. 文字と物はできるだけ太く大きく。色分けした文字は細い明朝系でなく太いゴシック系に
  4. **赤に注意**: 第一色覚では暗い赤はほとんど黒に見える。黒地（黒板を含む）に赤い字を置かない。純粋な赤（#FF0000）の代わりに朱色（RGB=100%, 32%, 0%、#FF2000 と書かれている）か、白を混ぜた明るい赤（#FF1414）を使う
- **色覚バリアフリーの配色**（Fig.16）の選び方: 赤は朱色、黄と緑の間の色は使わない、緑は青みの緑、紫は赤紫、朱色と黄の間に明るさの違う 3 色、空色と青は明るさと彩度の差で区別。**細い線と小さな字には空色と黄でなく、濃い青と橙を**。組み合わせるときは暖色と寒色を交互に、同じ系統を 2 つ使うなら明るさか彩度の差をはっきり、低彩度・低明度の組み合わせは避ける
- **発表のとき**: 色名だけで指さない（「この赤い細胞」でなく「左上の赤くて丸い細胞」）。赤いレーザーポインタは見えにくいので緑を
- **シミュレーションの注意**: 色覚の模擬表示は最も強い型（2 色覚）を真似たもので、全員がそう見えるわけではない。模擬で見える色がその人の感じる色とは限らない。模擬だけに頼らず当事者に見てもらえ、と書く

### WCAG 2.2

- **1.4.1 Use of Color（A）**: 「色を、情報を伝える・操作を示す・反応を促す・要素を区別する、唯一の視覚的手段にしない」。色の使用や色分けを抑制する意図はない、と注記。色相だけでなく**明るさの差が 3:1 以上あれば**、それを追加の視覚的区別として数える（明るい緑と暗い赤なら可）。ただし「緑は有効・赤は無効」のように**特定の色を知覚できること**に頼る場合は、コントラスト比に関係なく別の手がかりが要る
- **1.4.3 Contrast (Minimum)（AA）**: 文字と文字の画像は **4.5:1 以上**。大きな文字（18pt または 14pt の太字。CSS で約 24px・18.5px）は **3:1 以上**。純粋な装飾、他の視覚的内容が主の写真の中の文字、ロゴは除外。閾値は丸めない（4.499:1 は不合格）。アンチエイリアスで細い字は指定色より薄く描かれるので、太い書体か基準を上回る組み合わせを勧める
- **数値の根拠**（1.4.3 の Rationale）: 3:1 は ISO-9241-3 と ANSI-HFES-100-1988 が通常の視力に勧める最小値。視力 20/40 では**コントラスト感度がおよそ 1.5 倍失われる**という知見から 3 × 1.5 = 4.5:1。20/40 は「およそ 80 歳の高齢者の典型的な視力」と書く。20/80 では約 7:1 になり、これが 1.4.6（AAA）の 7:1。色覚の型は多様すぎて色の組を量的に処方できないので、**色に依らない明るさのコントラスト**を求める、と書く。例外として、第一色覚の人には長波長の色（赤）を暗い色の上に置くと見えにくく、「黒の上の赤」を避ける助言の技法がある
- **1.4.11 Non-text Contrast（AA）**: 内容を理解するのに要る**図の部品**（グラフの線、アイコンなど）は隣接する色と **3:1 以上**
- **コントラスト比の式**: (L1 + 0.05) / (L2 + 0.05)。L は sRGB の各成分を線形化して 0.2126R + 0.7152G + 0.0722B で求める相対輝度。比は 1:1〜21:1

### 参考: Tufte の掲示板の議論

- Tufte の ET Notebooks の色覚のスレッド（2002 年〜）は読者どうしの回答で、Tufte 本人の回答は無い。読者は「赤緑で色分けしない」「青と黄は見分けやすいが、黄は白地では細すぎる」と書き、2015 年の投稿が岡部・伊藤の CUD を紹介している

## 計算してみた（この担当の計算。文献の主張ではない）

CUD の配色の数値は原典のページでは画像だけなので、**他の文献で広く引かれる値**（Wong 2011 Nature Methods などに載るとされる値。**原典の画像とは照合していない**）で、WCAG の式を使って背景とのコントラスト比を計算した。

| 色（よく引かれる RGB） | 白地との比 | 黒地との比 |
|---|---|---|
| 橙 (230,159,0) | 2.25 | 9.32 |
| 空色 (86,180,233) | 2.31 | 9.10 |
| 青みの緑 (0,158,115) | 3.42 | 6.14 |
| 黄 (240,228,66) | 1.32 | 15.88 |
| 青 (0,114,178) | 5.19 | 4.05 |
| 朱色 (213,94,0) | 3.87 | 5.43 |
| 赤紫 (204,121,167) | 3.06 | 6.86 |
| 原典が書く朱色 #FF2000 | 3.85 | 5.46 |

- 白地では橙・空色・黄が図の部品の 3:1 にも届かない。CUD が「細い線と小さな字には空色と黄でなく濃い青と橙」と書くのと、白地では橙も足りない点は合わない（CUD の「橙」は細い線に使う前提の推奨で、背景を指定していない）
- 黒地ではどの色も 3:1 を超え、青だけが文字の 4.5:1 に届かない（4.05）

## この wiki への含意

- **色付きのラベルは文字と組なら 1.4.1 を満たす**: クオリアさんの動画は主張の種類を `実機確認`（cyan）／`人間評価`（pink）／`推奨`（gold）などの色付きラベルで区別した（[[exp-qualia-video]]）。ラベルの文字そのものが種類を言っているので、色だけで伝えてはいない。CUD の「凡例を離さず直接書く」とも合う。ただし cyan・pink・gold の組が色覚の型で見分けられるかは確かめていない
- **「現在位置は橙」は色だけの強調になりうる**: 般若心経の同期解説は「背景は黒に近い暖色、本文は大きなゴシック、現在位置は橙、注記は低コントラストの灰」で、変わるのは現在位置の強調色だけだった（[[exp-sutra-sync-subtitles]]）。WCAG の 1.4.1 の注記では、本文の色と橙の**明るさの差が 3:1 以上**なら追加の区別として数えるが、白い本文と橙では明るさの差が小さい可能性がある（計算していない。本文の色の値が経験ページに無い）。CUD の原則 2 に沿うなら、色に加えて太さ・大きさ・下線などの形の手がかりを重ねる選択肢がある。アゲアゲ版で「打つたびに約 1.9 倍に叩きつける」演出（[[exp-sutra-hype-editions]]）は、大きさの手がかりを重ねた例になっている
- **promo の暗い背景**: エヴァ OP 様式の明朝の白字幕（[[exp-polis-magi-op]]）は黒地に白で比は最大（21:1）。ただし細い明朝は CUD が「色分けした字は太い書体に」と書く条件と、WCAG がアンチエイリアスで細い字が薄く描かれると書く条件に当たる。360px 幅のスマホ試験を回していたのは、この点の実測に当たる
- **embed は会場の投影機の条件で見え方が変わる**: WCAG の比は sRGB の画面上の値で、投影や室内光は考えていない。Tufte の「実際の条件で見よ」（[[web-layout-tufte-data-ink-chartjunk]]）と合わせて、会場で確かめるしかない
- **話し手が色名で指すとき**: embed や talk でナレーションが「赤い線が〜」と言うなら、CUD の「色名だけで指さない」に当たる。「上の赤い太い線」のように位置・形を添える。これは台本の側の配慮で、画面の配色だけでは解決しない
- **「別版はサムネイルの配色で区別する」**（[[exp-sutra-videos-overview]]）: 経験では冒頭の言葉・配色・帯の 3 つを変えていて、配色だけに頼っていない。1.4.1 と同じ形

## Open Questions

- WCAG は Web コンテンツの基準で、動画の 1 コマ・字幕の焼き込みにそのまま当てる根拠は WCAG 自身には書かれていない。動画の配信面（YouTube・X）の字幕の基準は別の担当の領域
- 動画は BT.709 の色域・限定範囲（16–235）で符号化されることが多い。sRGB 前提の WCAG の式をそのまま使ってよいかは確かめていない
- CUD の配色の RGB の数値は原典では画像で、上の表の値は二次の文献による。原典の画像の値、日本の CUDO の推奨配色セット（別の版）との違いは確かめていない
- 色覚の多様性を持つ人に西尾の動画を見てもらった記録はこの wiki に無い。CUD は「模擬表示だけに頼らず当事者に見てもらえ」と書く
