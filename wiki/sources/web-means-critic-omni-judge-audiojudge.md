# 音つきの動画・音声をモデルに評価させたときの実測（Omni-Judge・AudioJudge ほか）

## 何の文献か

3 本とも arXiv のプレプリント（査読の有無は表紙からは不明）。PDF の本文を読んだ。

- **Omni-Judge**: 音つきの生成動画（Sora 2・Veo 3）を、オムニモデル Qwen3-Omni（30B-A3B）に 9 つの指標で採点させ、人の採点と比べた
- **AudioJudge**: 音声モデル（GPT-4o-Audio、Gemini 2.5 Flash）を音声の評価役にする方法を系統的に試した。英語・タイ語のデータ
- **Louder, Longer, Livelier**（Netflix でのインターン研究）: 音声の評価役 6 つ（Qwen2.5-Omni ベースの専用モデル 4 つと Gemini 2.5 Pro・Gemini 3.1 Pro）に、音量・内容の豊かさ・感情の表し方を操作した音声を聞かせた監査

## 書いてあること

### Omni-Judge（2026-02）

- データ: 300 のプロンプトを Sora 2 と Veo 3 で動画にし、音声と映像の生成の研究経験のある博士課程の学生 6 人が 9 指標を 1〜5 点で採点（§3.3）
- 方式: 指標ごとに 1 つの指示文（目的・入力・1〜5 の採点基準）と、要るモダリティだけを入れる（例: 音と映像の同期は音＋映像、音の美しさは音だけ、3 者の一致は生成プロンプト＋抜き出したコマ＋音）（§3.5）。指示文は人の採点の分析から作り、動画の質では「色のちらつき・明るさの変化・**コマの停止**・時間の不連続」を、同期では「口の動きと発話、動作と音のタイミング」を見るよう書いている
- 人との相関（Kendall τb / Spearman ρ / Pearson r、Sora 2 と Veo 3、Table 2 から）:

| 指標 | Omni-Judge（Sora 2） | Omni-Judge（Veo 3） | 比べた既存の指標 |
|---|---|---|---|
| 音とテキストの一致 | 0.292 / 0.345 / 0.282 | 0.224 / 0.259 / 0.220 | CLAP 0.122〜0.171（τ） |
| 映像とテキストの一致 | 0.142 / 0.148 / 0.154 | 0.074 / 0.079 / 0.127 | ViCLIP 0.073〜0.086（τ） |
| 音・映像・テキストの一致 | 0.139 / 0.151 / 0.136 | 0.203 / 0.223 / 0.217 | ImageBind 0.070〜0.216（τ） |
| 音と映像の同期 | 0.142 / 0.156 / 0.167 | **0.045 / 0.050 / 0.136** | Synchformer 0.178〜0.224（τ） |
| 動画の質 | **0.020 / 0.021 / −0.002** | **−0.041 / −0.042 / −0.031** | ID 一貫性・動きの指標も低い |
| 音の質 | 0.161 / 0.181 / 0.206 | 0.090 / 0.103 / 0.123 | ― |
| 映像の美しさ | 0.200 / 0.219 / 0.298 | 0.083 / 0.089 / 0.216 | Aesthetic Predictor 0.033〜0.271（τ） |
| 音の美しさ | 0.253 / 0.285 / 0.290 | 0.129 / 0.149 / 0.162 | AudioBox-Aesthetics 0.063〜0.253（τ） |

- 著者の解釈: 「意味の理解が要る指標では既存の指標並みかそれ以上」「動画の質と音と映像の同期のような**高 fps の知覚の指標では劣る**。時間の分解能が足りず、色のちらつき・明るさの変化・**コマの停止**・音と動きの細かなずれを見つけられない」（§4.2）
- 点の水準もずれる: 同期の平均点は Omni-Judge 4.37 に対し人 3.41（Sora 2）、3 者の一致は 4.73 対 4.02。音とテキストの一致は逆に 2.52 対 3.82（Table 2）。**甘い指標と辛い指標がある**
- fps の比較（§4.3、Fig. 5）: 思考つきのモデルのほうが総じてよい。動画の質は 3 fps で最もよい（τ 0.126）。同期は 5 fps で最もよい（τ 0.144）。「fps と性能の関係は単調でない」

### AudioJudge（2025-07）

- 課題（Table 1、GPT-4o-Audio、2 本の音声を比べる正答率）: 発音の正確さ・話す速さ・同じ話者か・音声の品質（3 データ）
- **素のプロンプトでは発音 46.0%、話速 46.9%（偶然 50%）**。音声の品質は 65.5〜70.5%。人の正答率は発音 69.5%、話速 77.8%、話者 83.0%
- 文字起こしを添えても大半は上がらない（正解の文字列を添えると発音だけ 63.0%）
- **音声を 1 本につなげて渡す**（例と試験の音声を連結し、その間をテキストで挟まない）と上がる: 4 例＋連結で発音 66.5%、話速 55.3%、話者 70.0%。「音声の区切りの間でモダリティが切り替わらないことが、直接の比較を助ける」と書く
- システムの順位（13 の音声対話システム、人の判定 508 件、SpeakBench）: Spearman で GPT-4o-Audio 0.731 → 工夫で 0.775、Gemini 2.5 Flash 0.846 → 0.857、観点を分けた評価役の組み合わせで最大 0.91（要旨）。**これはシステムの順位の相関で、1 本ずつの判定ではない**
- 偏り: 長い応答を好む（verbosity）、最初に聞いたほうを好む（position）。雑音には比較的強い（§6）

### Louder, Longer, Livelier（2026-09）

- 操作: 同じ音声の RMS だけを ±3・±6dB 変える（基準は −30 LUFS）、意味が同じで内容の豊かさが違う文、感情（中立・喜・悲・怒）の読み分け。人の較正は英語の母語話者ほか 15 人、449 判定
- **2 本を比べさせると、5 つの評価役すべてが +6dB の大きいほうを選んだ**（平均 0.578、0.541〜0.616）。人も +6dB を選ぶ（0.612）が、音量の差は話し方の質の差ではない、と著者は書く。1 本ずつの点数（pointwise）では差が出にくい（§4.1）
- 内容の豊かな発話を、人（0.547）よりずっと強く好む（評価役の平均 0.71）。長さだけ・繰り返しでは勝たない（§4.2）
- **理由の文は、判定を変えた音の手がかりをほとんど名指ししない**: 音量に関する語（loud、quiet など）は監査した理由に現れず、無音・内容の豊かさの語も数%以下。感情も、どの感情に変えたかを言わず「抑揚」「品質」などの一般語で済ませる（§5）

## この wiki への含意

- **「音と映像を一緒に見せれば、同期のずれ・コマの停止に気づく」は、2026 年初めの公開オムニモデルでは成り立たない**: Omni-Judge の同期の相関はほぼ 0〜0.16。西尾の promo の拍合わせ（曲のドロップと画面の切り替え、[[exp-polis-magi-op]]、[[exp-sutra-sync-subtitles]]）の確認は、ffmpeg の機械検査と人の耳目の仕事のまま。howseen が「ドロップは自動の拍の格子を信じず帯域のエネルギーで見つける」と書いた（[[web-opus-howseen-claude-motion-design]]）のと同じく、時間の細部は信号処理のほうが確か
- **「コマの停止」を見つけられない**: 西尾の talk は静止を既定にしている（[[exp-qualia-video]]）ので、ここは逆に問題にならない。promo の「1 秒を超えて止めない」（howseen）の検査をモデルに任せるのは不可。コマ間差分で数える
- **TTS の読みの判定をモデルの耳に任せない**: AudioJudge で発音の比較は素のまま偶然と同程度。[[exp-galleria-tts-and-singing]] の「F0 の統計も Whisper の一致も良し悪しの判定にならず、最後は耳」と同じ向きの結果。使うなら「文字起こしして台本と照合」（言葉の誤りを拾う）までで、声質・自然さの判定は人
- **音声の評価役は大きい音を良いと言う**: TTS の候補や BGM の版を評価役に比べさせる前に、**ラウドネスを揃える**。これは galleria で TTS を比べたとき「試聴用コピーだけ発話中 RMS を −22 dBFS に揃えて音量差に引っ張られないようにした」（[[exp-qualia-video]] の makingof の comparison）のと同じ手当てで、人の耳にも評価役にも要る
- **理由の文を鵜呑みにしない**: 評価役の「〇〇だから良い」は、判定を変えた本当の手がかりを書いていないことがある。批評役の指摘は、時刻を見て人が確かめる前提で使う
- **意味の一致はまだ使える側**: 音とテキスト（ナレーションが台本どおりか、効果音がプロンプトに合うか）は Omni-Judge で最も人に近かった（それでも ρ 0.26〜0.35）

## 着手の仕方（未検証。galleria で確かめる）

- **何ができるようになるか**: 音声トラックの批評を「モデルに聞かせる部分」と「信号処理で測る部分」に分ける。モデルには言葉（何と言っているか、台本と合うか、効果音が場面に合うか）だけを聞き、音量・同期・停止は ffmpeg で数える。型: talk（ナレーション）・promo（BGM と拍）
- **機械**: galleria WSL（ffmpeg）。モデルの側は Gemini（**要: API キー・費用（西尾が決める）**、[[web-means-critic-gemini-video-understanding]]）か、ローカルの Qwen2.5-Omni-7B-AWQ（[[web-means-critic-qwen-omni]]）
- **成熟度**: 研究の結果を手順に移したもの。西尾の作品で試した例は無い
- **最小の手順**（ffmpeg の部分は一般的なコマンド。モデルへの問いの分け方はこのページの提案）:
  ```bash
  cd ~/video-tools-trial/critic
  # 1) 比べる前に音量を揃える（候補ごとに）。2 パスの厳密な揃え方は別ページの担当（check-spec）
  for f in tts_a.wav tts_b.wav; do ffmpeg -i $f -af loudnorm=I=-23:TP=-2 -ar 48000 norm_$f; done
  # 2) 音声を 1 本につなげる（AudioJudge の連結。間に 0.5 秒の無音）
  ffmpeg -i norm_tts_a.wav -i norm_tts_b.wav -filter_complex \
    "[0]apad=pad_dur=0.5[a];[a][1]concat=n=2:v=0:a=1" pair.wav
  # 3) 画面の停止を数える（モデルに聞かない）: 1 秒以上同じ画面が続く区間
  ffmpeg -i in.mp4 -vf "freezedetect=n=0.001:d=1" -an -f null - 2>&1 | grep freeze_
  ```
  モデルには `pair.wav` を渡し「前半と後半で、台本『（台本の文）』と言葉が違うのはどちらか、どの語か」とだけ聞く。声の良し悪しは聞かない
- **動いたと言える確かめ方**: `norm_*.wav` のラウドネスが揃う（`ffmpeg -i norm_tts_a.wav -af ebur128 -f null -` の Integrated が −23 付近）。`freezedetect` が `freeze_start` / `freeze_duration` を出す（talk では多数、promo では 0 が期待）。読み間違いを 1 語仕込んだ版で、モデルがその語を挙げるか
- **所要（推測）**: 2〜3 時間

## Open Questions

- Omni-Judge は 2026-02 の公開の Qwen3-Omni での結果。Gemini 3.8 Flash・Gemini 4 Argon の同期の判定は測られていない（Gemini は既定で 1 fps、音声は 1 チャンネルに落とす。[[web-means-critic-gemini-video-understanding]]）
- AudioJudge の課題は英語・タイ語。日本語の読み（「空」を「から」と読むか、[[exp-qualia-video]]）の判定は測られていない
- 評価役が大きい音を好むのは「比べさせたとき」に強く出る。1 本ずつ点数を付けさせる形なら避けられるのか、単に見えなくなるだけか（著者は後者を示唆）
