## 起点（西尾の発言、そのまま）

- 「tsugigamiを題材にしましょう。このサービス自体はさほどすごいものではないが、良いところを見つけてアピールするチャレンジに良い。iPadやApple Pencilというおしゃれデバイスの見た目の活用もできる。」
- 「一般人が見て「すごい！かっこいい！使おう！」などの感情を引き起こすような動画を作って。これはあくまでキャッチーな説明動画を作る実験である。」エンジニア向けの点（GitHub へのバックアップ、PWA）は扱わない
- 「実写にはしない、iPadにはめ込み合成したかっこいい動画を作る手段があるはず。必要なら好感を持たれるような日本人女性による使用シーンを生成して使って。本物の手書き線は使わない、女性的なきれいな手書き文字を使って。」

## 作り

```
make_layout.py  紙の中身の設計図（題・短い語・図・矢印・走り書きの波線）
  → strokes.mjs   書体（Yomogi、OFL）から Zhang-Suen の細線化で芯線を取り、字ごとに少し傾けて点列に
  → capture.mjs   公開中の tsugigami を headless Chrome（834×1194 @2x）で開き、合成の PointerEvent（pointerType 'pen'）で書く・メニューを押す・view を動かす。1 コマずつ PNG
  → compose.html  CSS の 3D 変換で iPad を斜めに置いて画面にコマを貼る、DOM で描いた Apple Pencil、字幕
                  人物の場面は、生成動画の画面の四隅へ homography（matrix3d）でコマを貼り、白い画素だけのマスクで手と Pencil を上に残す
  → render.mjs    renderFrame(f) を 1 コマずつ撮って ffmpeg へ
  → bgm.py        numpy で BGM（120 BPM）と効果音
人物: galleria の Grok Imagine（静止画 grok-imagine-image-2.0 → 動画 grok-imagine-video-1.5 の image-to-video）
  → prep_clip.py  1080×1350 に切り、画面の四隅を毎コマ追跡、マスク
  → ink_marks.py  モデルが画面に描いた薄い線を黒いインクにする（下）
```

画面の中身は全部、公開中のアプリの実物の動作。生成したのは人物の場面だけ。[[work-promotion-video]] の暫定の答え（実物の収録を正本に、丸ごと生成は中身を見せないカットに限り、使ったら開示）と同じ形になった。作り方の共通部分は [[exp-html-capture-pipeline]]。

## 分かったこと

### 実アプリを録る

- **自動操作は、操作のあとに状態を確かめる。** 右の紙が机の色のままだったのを「アプリの不具合」として CyEC2 に依頼したが、CyEC2 の切り分けで、録画スクリプトがメニューを開いた後につまみをもう一度押してメニューを閉じていたと分かった。紙は継がれていなかった。継いだ後に紙の幅を確かめて、違えば止めるようにした
- **場面は、前の場面が終わったコマから始める。** 横へ滑る場面が右の紙に書き始めるコマまで流れ、次の場面が同じコマから始めていたため、「10月」と線が 2 回書かれていた（v5 で西尾が指摘）。録画にタグ（menu, widened, right-write, zoom-out …）を付け、各場面の始まりと再生倍率を前の場面の終わりから計算する
- **場面の間をカメラの動きでつなぐなら、録画の側でつなぐ。** 「今日の紙」から長いノートへの切替を滑らかにするには、長いノートの録画を、前の場面の最後と同じ紙（題・3 行）を一番下に置いた状態から始め、そこから引いて流すように撮り直した。iPad の 3D の姿勢も前の場面の終わりの値から続ける
- **読ませない走り書きは速く書く。** 字と同じ速さで書くと「意味のないことを書いてる時間」になる。走り書きだけ 5 倍速にし、画面で書くのは題・3 行・月の軸だけにした

### 手書き風の字

- 書体から芯線を取って揺らす方法では、西尾の基準の自然さに届かなかった。整いすぎの正体は字形より「全部の字が同じ大きさ・傾き・基線」だったが、揺らすと今度は線が途切れて見える。最後は「読ませる字は少なく、崩しは最小、読ませない部分は走り書きの波線」で落ち着いた
- 芯線の追跡が途切れる原因は 3 つあった: 斜めの階段を分岐と見なす（crossing number と 4 近傍優先で直した）、太さ 2 画素の箇所（最後に 1 回細線化）、閉じた輪（0・9）を RDP が 1 点に潰す（一番遠い点で 2 つに割る）

### 生成した人物の動画にアプリをはめ込む

- **四隅は、前のコマの四辺の近くの輪郭で直線を引き直し、隣の辺と交わる点として取る。** 白い領域の凸包から四角形を取る方法は、手が角を隠すと角が欠け、四隅の順番も回転で入れ替わった。直線の交点なら手に隠れた角も出る。カメラも iPad も動かない動画は全コマの中央値で固定した方が揺れない
- **画面の向きは「誰が画面を読む側か」で決まる。** 正面から撮った女性も、肩越しの手元も、本人は画の上側にいるので、画面の上端は画の下側に来る。v4 と v5 はアプリを見る人の向きに貼って、西尾に 2 回「逆」と言われた。galleria の Claude は肩越しの o1 を「回さなくてよい」と判定していたが、誤りだった
- **iPad が枠の外へ出る動画は使えない。** 顔を上げて微笑む候補が 2 本あり、うち 1 本は途中で iPad が下にずれて角が枠外に出たので、追跡できなかった。依頼に「四隅が全フレームで枠の内側」と書いても守られないことがある
- **マスクの閾値は 2 本に分ける。** 画面を見つけるには厳しい閾値（白い Pencil と手が画面とつながらないように）、マスクには緩い閾値（手の影の中の画面もアプリで覆うように）が要った
- **モデルが画面に描いてしまう薄い線は、Pencil の真下のインクとして使える。** 「画面は真っ白のまま」と頼んでも、Grok Imagine は書く動きに合わせて薄い線を描いた（6 本中、程度の差はあれ多く）。この線は Pencil の先の真下に出るので、周りより細く暗い画素（black-hat）が数コマ残り続けるところだけを黒く濃くし、マスクから外した。インクがペン先に同期する。Pencil の先を追跡してアプリに書かせる方法は、薄い線に引っ張られて不安定だった。代わりに、その場面のアプリの紙は題だけの状態で止めた
- 書き込みの中身はモデルが描いた線なので読めない。読ませる字ではなく「書いている」ことを見せる場面に限る

### 冒頭

- 西尾「冒頭数秒でキャッチするべきって話では？」。各社の資料は最初の 3〜5 秒（[[promo]]）。v4 までは「ただ、書く。」から始め、この作品にしかない動き（紙を継ぐ）が 10 秒過ぎだった。v5 から最初のコマに「紙が、足りない。」を出し、2.2 秒で継ぐ。Derek Lieu の「作品にしかない hook を見せる」（[[work-promotion-video]]）と同じ向き
