# Common Craft の台本の書き方（Lee LeFever）

## 何の文献か

- **著者・媒体**: Lee LeFever。妻の Sachi と Common Craft を営む。About ページは、2007 年に *In Plain English* シリーズを作り「今 **explainer video** と呼ばれるジャンルの火付けに関わった」と書いている。著書 *The Art of Explanation*（Wiley, 2012）
- **種類**: 実務家の手引き（制作会社が配った台本テンプレート、全 8 ページ、Word で作られた PDF、作成者 Lee LeFever、作成日 2013-02-24）と、本人のニュースレター・ブログ記事。研究ではない。自分の講座（Explainer Academy、有料）への誘導を含む宣伝の面もある
- 著書 *The Art of Explanation* の本文は読んでいない（目次の章名「Agreement, Context, Story, Connections, Description, Conclusion」と、6 章に「On the Explanation Scale」節があることを検索結果の書誌情報で見ただけ）。この手引きは同じ枠組みを台本の形にしたもの

## 書いてあること

### 尺と語数（手引き「Form and Flow - Duration」）

- Common Craft の動画は「たいてい 3 分以下」。理由は「3 分が、たいていの人がオンライン動画に注意を払う最大の長さだ、という考え」と書いている。「多くの場合、短い方が良い」。根拠のデータは示していない
- 「台本の書き方と読む速さによるが、3 分の台本は 425〜525 語と見積もる」。毎分にすると約 142〜175 語（この換算はこのページの計算）。書きながら語数を数えるよう勧めている
- About ページでも「約 3 分で、簡単な絵と親しみやすい声のナレーションで考えを明確にする」と自社を説明している

### 順番は「Why? → How?」（手引き「Form and Flow – Content」）

- 「たいていの説明は二つの問いに順に答える。“Why?” と “How?”」
- **Explanation Scale**（A〜Z の目盛り）: 話題を知らない人（A 側）向けの説明は「なぜ大事か」に重みを置き、よく知っている人（Z 側）向けは「どう動くか」に重みを置く。例として、拡張現実を知らない聴衆は「C」あたりにいて「なぜ私に関係あるのか」を問うので、それに早く答えると「どう動くか」まで付いてきてもらえる。家の断熱のように誰でも理由を知っている題材なら「どう動くか」に寄せる
- 同じ考えを 2024 年ごろの記事では JPEG の圧縮にたとえている。**baseline**（1 行ずつ完全な解像度で描く）は聞き手が自分と同じくらい知っているとき、**progressive**（ぼやけた全体から細部へ）は聞き手にとって新しい考えのとき。「新しい概念の導入や、文脈が役に立つときに向く」と書いている（what-jpegs 記事）

### 台本の骨格（手引き「Drafting a Script」）

| 部 | 要素 | 手引きの説明 |
|---|---|---|
| Introduction | Agreement | 何の話で、なぜ大事か |
| | Context | 大きな絵のどこに収まるか |
| Body（全部使わなくてよい。題材に合うものを選ぶ） | Story | あなたのような人が新しいことを知る |
| | Connection | すでに知っている何かに似ている（たとえ） |
| | Description | 基本がわかったので、細部の話 |
| Conclusion | Realization | なぜ大事か・どう動くかが腑に落ちる |
| | Call to Action | 次に何をするか |

各要素について手引きが書いていること:

- **導入**: 「説明の目的は、聞き手に“わかった”という自信を持たせること。早く自信を失うと早く離れる」。だから最初の数文は「議論にならず、うなずいてもらえる」文で文脈を作る。例「コンピュータはかつて家や会社の中で単独で動いていた。でもインターネットのおかげで、まったく別の場所にあるコンピュータの力を使える。それを“クラウド”と呼ぶ」（Cloud Computing）
- **Story**: 「Bob はあなたに似ている → Bob は困っていて気分が悪い → 最近 Bob は解決策を見つけて気分が良い → Bob のようになりたくない？」という弧。登場人物の気持ち（好奇心・板挟み・ストレス）を書くよう求めている
- **Connection**: 「ボートは車に似ているが、道でなく水の上を進む」のようなたとえを「理解への近道」と呼ぶ。例: ハードディスク＝家の地下室、検索エンジン＝世界中の本の司書
- **Description**: 「How?」の部分。「動画では説明（手順）は追いにくい。指示を多くしすぎると聞き手は自信を失って離れる。大きな点に絞り、人が覚えていそうにない細部は減らす」
- **Realization**: 「すべてがはまる、電球がつく瞬間」を、多くは物語の中で登場人物が気づく形で見せる
- **Call to Action**: 行き先・読むもの・問い、あるいは「世界を違う目で見よう」という一言でもよい
- **書き直し**（「Write and Iterate」）: 「一度で正しく書けることはまれ。鍵は反復」。声に出して読み、友人に読んでもらい、語数を確かめ、「本質的でない考えを削って短くする準備をいつもしておく」

### ニュースレター・ブログで本人が書いていること

- **知識の呪い**（2022-11-02 の記事）: 「題材をよく知るほど、初心者に説明するのが難しくなる」。対策として、一語ずつ見直す（例: 金融の専門家が若い夫婦に「amortization」と言う）、聞き手の立場に立つ、宛先の人と実際に話して語や例を確かめる、簡単にしすぎて見下した印象にならないよう「基本から始めます」と前置きする、の 4 つを挙げている
- **事実と物語**（2024 年 1 月ごろ）: 悪い説明の犯人は多くが「fact telling」——文脈も物語もなく事実を並べ、意味を聞き手に考えさせること。著書で最もよく引かれる一文として「Facts give stories substance. Stories give facts meaning.」を挙げている
- **注意**（2026 年ごろ、新しい連載 *The Science of Explanation* の紹介）: 注意は「脅威・新しさ・目標に関わるもの・感情に関わるもの」に向く、と書き、「どんな説明でも冒頭が決定的」と結んでいる。Broadbent らの注意研究を 2.75 分の動画で解説したと書いている（研究そのものはこのページでは確かめていない）

### 型の分け方について

- About ページは自社の動画を「チュートリアルや手順の説明と違い、**概念と文脈**に焦点を当てる。物語を語り、たとえを使う」と書き、教育者が「新しい話題の導入、より深い学習の下地づくり、全員に大きな絵を見せる」ために使う、と書いている
- Common Craft が分けているのは「概念・文脈の説明」と「手順の説明（tutorial）」で、プロモーションと解説の区別ではない。手引きの例（Cloud Computing、Crowdsourcing、Twitter など）は製品の宣伝でなく概念の説明。一方で Call to Action を結びに置くのは宣伝動画と同じ形

## この wiki への含意

- **embed にいちばん近い実務の型かもしれない**。Common Craft の動画は「約 3 分・1 概念・授業の中で導入として流す」と自社が書いており、西尾の言う「プレゼンの中に埋め込んで使う特定概念を解説するもの」の使われ方に近い。[[three-video-types]] で embed は経験がない型なので、この骨格（Agreement → Context → Connection → Realization）は embed の最初の試作の台本の型として試せる（未検証）
- **冒頭で「なぜ」を作る**は、クオリアさん journey で人間の評価「最初の1分で目的と関心を作る」を受けて冒頭 52.9 秒で目的・失敗・チェックリストを予告した改稿と同じ向き（[[exp-qualia-video]]）。Common Craft は根拠を「聞き手が自信を失うと離れる」に置いている
- **「人が覚えていそうにない細部は減らす」**は、クオリアさん journey の「細かい数値を耳で聞くのが辛い」→ version・seed・hash を読み上げない、と一致する（[[exp-qualia-video]]）
- **「fact telling」の批判**は、Gyazo の動画の元の構成案が「作業の順に数字を並べる作業報告」で山がなかった、という経験と一致する（[[exp-gyazo-resumption-video]]）。ただし Gyazo では物語に組み替えた v1 が今度は主役の技術を薄くし、西尾に「Visual Jev の話も超重要」と言われた。Common Craft の言う「Facts give stories substance」の側の失敗にあたる
- **Explanation Scale（宛先がどこにいるか）**は、LLM Wiki 1 分シリーズで西尾が最初に決めた「宛先＝一般の知的生産層、Claude Code をまだ使っていない人」と、そこから「専門用語を出さない」を導いた手順と同じ（[[exp-llm-wiki-explainer-series]]）。Gyazo の「268群って何？」も知識の呪いの例と読める（[[exp-gyazo-resumption-video]]）
- **語数で尺を見積もり、声に出して確かめ、削る準備をしておく**は、LT で 300 字/分で見積もり、合成音声で読ませて尺を測り、削る順を先に決めた手順と同じ（[[exp-lt-20260909]]）。英語の 425〜525 語/3 分と日本語の 300 字/分は単位が違うので直接比べられない
- **Story（Bob の弧）**は西尾の経験に対応する例がない。クオリアさんは語り手であって「あなたに似た、困っている人」ではない

## Open Questions

- 手引きは 2013 年のもの。2026 年の Common Craft が同じ型を使っているかは、現行の講座（有料）を見ていないので分からない
- Story（登場人物の困りごと → 解決）は宣伝動画と解説動画で同じように効くのか。「Don't you want to feel like Bob?」は宣伝の言い回しに近い。embed（話し手が横にいる場）で登場人物の物語が要るかは未検証
