# howseen-ai「claude-motion-design」— 自社のローンチ動画から育った skill

## 何の文献か

- Claude Code の skill（MIT）。作者は AI の可視性を測るサービス Howseen の創業者で、README の例は自社のローンチ動画（24 秒、「Claude Opus 5.5 とこの skill で 5 回の反復」）。**自社の宣伝を兼ねた repo**である点に注意
- star 795・fork 101（2026-11-09 に GitHub API で取得）
- SKILL.md は作者の作業環境のパスや社内の決まり（「Howseen の名前を AI 生成画像に入れない」など）をそのまま含む、個人の作業記録に近い文書。冒頭に「2026-09-25〜27 に、60 秒の VO 付き広告、ループ、ローンチ動画、ショーリール v1/v2、LinkedIn 用 v1→v5 などで作って試した」とある。節の日付から、10-02 まで書き足されている
- 他の公開 skill・YouTube の解説・「Playbook Opus 5.5」という文書から取り込んだ規則を、出どころの名前つきで節に分けている（§9b〜9d）

## 書いてあること

### 譲れないこと（§0）

- **画面で捏造しない**: 実データは画面に出典を出す（例「ログアウト状態の ChatGPT の回答 12 件・2026-09-25」）。説明用のものは「Example data」「Illustration」と画面に書く。存在しない機能を主張しない（アプリのコードで確かめる）
- **キャプションを正直に**: 10 分でなければ「10 分で作った」と書かない。外部の道具を使ったなら「外部ツール 0」と書かない。**反復したなら「one shot」と書かない**
- 作品のフォルダに `facts.md` を置き、全部の数字に出典と日付を書く。「facts.md が無ければ画面に数字を出さない」（§9b）

### 流れ（§1）と描画（§2・§3）

- 入力（依頼文に `<inputs>` があれば聞く）→ 拍の地図 `BEATMAP.md`（**曲のドロップを鍵の場面に合わせる**。1 秒を超えて止まっているものを作らない）→ **静止画 4 枚**（か 1 拍 1 枚のシート）を見て直す → 全編のレンダリング → 「ポップ」の検出 → 音 → 合成
- 描画は `window.seek(t)` だけ。CSS transition・タイマー・コマ間の状態なし。ばねは閉形式。カメラのズームは対数空間で補間し、ズームインとアウトを続けない
- 撮影は Playwright。フォントの準備を待ち、Web Animations を止め、**`seek(t)` のあと requestAnimationFrame を 2 回待ってから撮る**。下書きは 960×540・30fps で「シャープさでなくリズムを見る」。本番は 60fps で 1 コマに複数のサブフレームを 180° シャッター相当で混ぜる（ハードカットをまたいでぼかさない）。25 秒を超える作品は 3 並列に分けて撮る（55 秒で約 20 分、逐次なら約 55 分と書いている）
- 自動検査: コマ間差分が近傍の 3 倍を超える「ポップ」と 1 コマだけの閃光の検出（意図した拍のカットも引っかかるので、隠さず言う）、ループの継ぎ目を**位置と速度の両方**で確かめる
- 最終のエンコードは BT.709・TV レンジ、libx264 crf 16。ラウドネスは −14 LUFS（二段階）

### 音（§4）

- 曲は Mixkit（無料・商用可）。**ドロップは自動の拍の格子を信じず、帯域ごとのエネルギーで見つける**（ある曲では自動の格子が 2 拍ずれていたと書いている）。効果音は測ったピークの位置に置く
- 声は Cartesia の TTS と単語のタイムスタンプ、声の下で音楽を約 9dB 下げる

### 批評ループ（§8・§9b・§9c）

- §8 は Movez の形: コンタクトシート（2fps・270px 幅）、連続 12 コマ、スマホ幅（360px）、ループ確認を ffmpeg で作り、7 軸で 1〜10 点、ワースト 3 をタイムスタンプ付きで、全項目 8 以上まで
- §9b（「Playbook Opus 5.5」から）: 1 拍ごとと拍の 0.3 秒後のコマを撮り、**ショットごとに**10 点満点で採点、7 点以下だけ直し、9 点以上のショットには触らない。2〜4 回で「AI っぽさが消える」と書いている
- **§9c「作る者と裁く者を分ける」**: 批評は別の読み取り専用のサブエージェントでやる。**新しいエージェントにコマだけから伝えたいことを言い直させ、言えなければその作品は不合格**
- 冒頭（§00）の実例: launch20 では 3 体の制作エージェントが並列にショット群を作り、**動きの批評役とデザインの批評役を別々の読み取り専用エージェントにして「既定は却下」**、修正を担当ごとのファイルに分けて v2 を作った（約 2 時間）。批評役から学んだこととして「最後の静止以外、どこにも凍ったコマを置かない（終わりのカードにも微小な動きを残す）」「次のショットは前のショットの退場の向きに既に動きながら入る」などを挙げている
- **人の試験（§9b）**: ループを**音を消して**人に見せ、一文で要約できたら成功（「ボタンがプレーヤーになった」）。ためらったら動きすぎ

### AI 製に見える動きへの決まり（§9b）

アクセント色は 1 つ。**一度に動くのは 1 つ**（スライダーが連続変形を駆動する場合を除く）。最初から最後まで一つの形・視覚の体系で、カットでなく変形。ばねの減衰比は 0.72 以上で、漫画的なバウンス禁止。禁止: 虹色グラデーション、パーティクル、発光する UI の縁、絵文字、lorem ipsum、意味のない 3D フリップ。文字はスマホで読める大きさ、9:16 の安全域は絵コンテの段で決める（文字は中央の 1080×1080 に）。

### 「醜いときの診断」表（§9b）から

- 「X に流れているのと同じ動画になる」← Livera のプロンプトを決まりも状態も無しに貼った → 指示書・facts・名前のある様式を足す（[[web-opus-stephanlivera-showreel-prompt]]）
- 「機能を捏造した」← スクリーンショットも repo も facts.md も無い
- 「コストが膨らむ」← 小さな修正に effort max → 修正は medium

### その他

- 既存のローンチ動画をコマ単位で写して自社版に置き換える「リメイク」モード（§10）がある。参照の音楽・声・人物写真は使わない、と書いている
- 解説・プロモ以外の使い道として、文書・手順書から説明動画、SVG のマスコットが語り手、提案書の動画版、静的な HTML スライドを 5〜20 秒の動くスライドのループに、を挙げている（§9d、YouTube の解説動画の書き起こしから）

## この wiki への含意

- **捏造しない・正直に書く決まりは、西尾の決まりとほぼ同じ形**: 西尾の 4 件は README に「画面の主張 → 一次ソース」の表を置き、確かめられない役割語は弱めるか出さず、動画で足したものを明記した（[[exp-html-capture-pipeline]]）。Gyazo では「AI」とぼかさずモデル名を出し、比較を同条件で測り直した（[[exp-gyazo-resumption-video]]）。howseen の `facts.md`・「Example data」の表示・「one shot と書かない」は同じ問題への同じ答え。違いは、howseen は自社の宣伝で、西尾は自分の活動の発信だったこと
- **「作る者と裁く者を分ける」「コマだけから要旨を言い直させる」は、西尾の経験の「人の評価が要る」を AI の側で近づける試み**。西尾の経験では評価は西尾の一言（「しょぼい」「展開が遅くてだるい」「268群って何？」）で、特に Gyazo の 12 行は**中身が伝わるか**への指摘だった（[[exp-gyazo-resumption-video]]）。「新しいエージェントがコマだけから要旨を言えるか」は、この種の指摘（意味がわからん、何の代表かわからん）を事前に拾う試験として、西尾の制作にない段。効くかは測られていない
- **「音を消して人に一文で要約させる」は、無音自動再生の場への西尾の対応（字幕だけで通じるように）と同じ方向**（[[exp-words-as-public-goods-video]]、[[exp-democracy-river-video]]）。人を使う試験を skill の中に置いている点で、AI の自己採点だけの hculap（[[web-opus-hculap-skill-motion-graphic]]）と違う
- **「1 秒を超えて止めない」「凍ったコマを置かない」は promo の決まり**で、西尾の promo の経験（死んだ拍、[[exp-polis-magi-op]]）と一致し、talk の経験（完全静止を既定に、[[exp-qualia-video]]）とは逆。「一度に動くのは 1 つ」は talk の経験（説明中の語・数値だけを強調）と合う
- 「静的な HTML スライドを 5〜20 秒の動くループに」は embed に近い使い道として挙がっているが、YouTube の解説の書き起こしからの又聞きで、作例は無い
