# PDoomVideo — モデルが自分で書いた house rules とサブエージェントの分担

## 何の文献か

- MV「I'm Upping My P(doom)」（156.6 秒、曲は 2024 年の YouTube 動画から、と README）の全ソース。repo の作成は 2026-09-22 23:32 UTC で、Opus 5.5 公開の当日。star 2,866（2026-11-09 に GitHub API で取得）。作者は続けて汎用の土台 ClaudeAnimationBase（star 2,754、同日取得）を出している
- Movez の記事は「章ごとにサブエージェント」の手本としてこの repo を挙げ（1.1K stars と書いている、9 月末時点）、hculap の skill も同じ（[[web-opus-hculap-skill-motion-graphic]]）。Donald Jewkes の長い依頼文は、作り直す元の動画の JS のソースとしてこの repo を渡している（[[web-opus-donaldjewkes-claude-pop-brief]]）
- README の制作の説明は作者の申告。ANIMATION_GUIDE.md と STORYBOARD.md は README によると Opus が書いたもので、**モデルが自分の配下のエージェントに渡した決まりごとの実物**として読める

## 書いてあること

### 作り方（README）

- 2 世代、どちらも Claude Code。1 世代目（`legacy/`）は Claude Opus 5.5（Medium）、2 世代目（残り全部）は Claude Opus 5.5
- "Everything in this repository was generated by the model. No scene ideas were specified." 人の指示は「Clawd のキャラクターデザインを使う」「歌詞ごとに面白い絵と遷移を」だけ、と書いている
- STORYBOARD.md は 1 世代目のあとに Opus が書いた。そのときの指示は「p5 の筆致（p5.brush）を使う」「どの場面も見て面白く」「どの場面も次の場面へ遷移させる」
- ANIMATION_GUIDE.md は「並列に走らせたサブエージェントへの説明として Opus が書いた」

### 絵コンテの決まり（STORYBOARD.md）

- 構成: 舞台の幕が開き、同じ幕で閉じる。小さな AI（Clawd）がモニターの落書きから惑星大の超知能に育ち、最後の歌詞 "Was it all for show?" で全部が芝居だったと引いて見せる
- **全ショットの規則: 画面で何かが「起きる」**（キャラが何かする、何かが壊れる・変わる・追う・落ちる）
- **文字を少なく**: 冗談は絵と演技で伝える。大きな擬音（FOOM, BOOM…）を全編で数個だけ。物にラベルを貼らない、キャプションを付けない、歌詞を繰り返す看板を出さない（カラオケの帯が既に出している）。「文字の多いコマは悪く見える。迷ったら文字を外せ」
- 場面は「カードでなくセット」（章ごとに一つの場所をカメラが動く）、遷移は動機づける（章の切れ目は筆のワイプ、章の中は動作がカットを運ぶ）、表情は切り替えでなく「つぶれ → 伸び → 記号が飛ぶ → 新しい目」、全ショットにカメラの動き、章ごとの色の弧

### 決まりごと（ANIMATION_GUIDE.md）

- 冒頭: "Animation guide (read this before painting a chapter)"。156.6 秒・1920×1080 を p5.brush の水彩で描き、headless Chrome でオフライン描画するので「速さより質、ただし予算内」
- **分担の決まり**: 章は `src/ch/` の 1 ファイル（IIFE で包み、補助関数は私的に）。**自分の章のファイルだけを編集する**。共有の補助関数が足りなければ自分の中に書く。共有ファイルに本物のバグを見つけたら報告し、直さない
- **描画の約束**: コマは並列かつ順不同に描かれるので、全ショットは t の純関数、コマ間の状態なし、Math.random 禁止（`hash(i)` を使う）。線の「ぼこぼこ」（手描きの揺れ）は `jit` を 1 秒 12 回種を替えて意図的に出す
- 画面の約束: 歌詞があるときは下端（y 975〜1070）にカラオケの帯が出るので、顔と動作は y 960 より上。章の切れ目のワイプとコーラス中の P(doom) メーターはタイムラインが自動で出す
- 拍: 88BPM（1 拍 0.682 秒）。重要な動作は拍の時刻（0.21＋n×0.682 秒）に置く
- 様式: 絵本のような水彩とインク。キャラは平塗りとインクの線、背景は柔らかい水彩。純黒・純白は避ける
- 動き: 全部動く（カメラは漂うか押す、キャラは拍で弾む）、つぶし伸ばし・予備動作・行き過ぎ
- **読みやすさ: 1 ショット 1 つの焦点の動作、大きなシルエット。ショットは短い（1.4〜4 秒）ので、ギャグは一瞬で読めなければならない**
- 重さ: 1 コマ 2.5 秒以内、約 4 秒を超えない。費用は塗りと線の数で決まる（数百は可、数千は不可）

### 確かめ方（ANIMATION_GUIDE.md「Checking your work」）

- `node render.mjs --sheet=38.6,39.3,...` で複数の時刻を 1 枚に並べ（1 コマあたりの描画時間も出る）、**Read ツールで開いて注意深く見る**
- 見る所: 各ショットの最初と最後のコマとその間の数コマ／ヒットの周りを 0.1 秒刻みで、動きが連続して読めるか／自分の章への出入りの遷移／カラオケの帯の下に重要な物が無いか
- 「魅力的で、読めて、生き生きして、キャラが崩れていない」まで直す。採点の数値は無い

## この wiki への含意

- **house rules を人が書くか、モデルが書くか**: Movez 以後の skill（[[web-opus-hculap-skill-motion-graphic]]、[[web-opus-howseen-claude-motion-design]]）は人が書いた決まりをエージェントに読ませる。PDoom は、人の短い指示から**指揮役の Opus が決まりを書き、並列の Opus に読ませた**。公開当日の作で、Movez の言う「一行 vs 長い指示書」のどちらでもない第三の形（人の指示は短く、長い指示書はモデルが書く）。西尾の制作は 1 体を直列に直し、決まりは人と AI の会話と README に残った（[[exp-html-capture-pipeline]]、[[exp-polis-magi-op]]）
- **並列の分担の決まり「自分のファイルだけ、共有は直さず報告」**は、Taelin の「アイデアは共有、コードは共有しない」（[[web-taelin-bend-nge-feedback]]）と同じ問題（並走で見た目の一貫性が崩れる）への別の答え。Taelin は別々の作品を競わせ、PDoom は一つの作品を章で割った
- **「文字を少なく」**は Taelin の往復（多すぎ → 少なすぎ → 関連するアニメのそばに大きな白いタイトル）と照らすと、PDoom はカラオケの帯が「何の話か」の手がかりを担っているので文字を絵から外せた、と読める。西尾の Polis（エヴァ OP 様式）は明朝の白字幕と映像の高速交互で、字幕が主役だった（[[exp-polis-magi-op]]）
- **確かめ方は「シートを開いて見る」だけで、点数も止める条件も無い**。西尾の「静止画・コンタクトシートで確かめる」（[[exp-html-capture-pipeline]]）に一番近い素朴な形。0.1 秒刻みでヒットの周りを見る指示は、静止画で動きを見る工夫として hculap の「連続 12 コマ」と同じ
- ショット 1.4〜4 秒は promo（MV）の尺。西尾の Polis の v2 で効いた「実物の OP の平均 1.07 秒」（[[exp-polis-magi-op]]）より長い
